# Мои значки — мини-приложение ВКонтакте без сервера

Каталогизация коллекций значков по фото. Значки, которые есть, показываются в цвете,
недостающие — серыми SVG-контурами.

Своего или арендованного сервера нет:

| Задача из ТЗ | Как сделано |
|---|---|
| Хостинг приложения | Статический хостинг VK Mini Apps (`npm run deploy`) |
| Вход по SMS | Не нужен: пользователь уже авторизован во ВКонтакте |
| Камера | Системная камера через `<input capture>` в клиенте VK |
| Детекция, обрезка, выравнивание | Пользователь наводит круг на значок (сдвиг и масштаб); поворот распознаванию не важен |
| Идентификация | На телефоне: нейросеть MobileNetV2 (onnxruntime-web) + цветовой дескриптор, поиск ближайшего эталона (`src/recognition`) |
| Векторизация SVG | Заранее, для всего каталога (`tools/build_catalog.py`): контуры нужны и для значков, которых у пользователя нет |
| Цвета из метаданных | Палитра (k-means) лежит в `catalog.json` |
| БД значков | Статические `catalog.json` + `embeddings.json` + картинки (VK-хостинг или GitHub + jsDelivr) |
| Коллекции пользователя | VK Storage (`VKWebAppStorageSet`), `src/storage/kv.ts` |

## Запуск

```bash
npm install          # заодно копирует движок нейросети в public/ort/
npm run dev          # http://localhost:5173: в браузере данные хранятся в localStorage
npm run typecheck
npm run build        # сборка в dist/
npm run demo         # одна HTML-страница со вшитым каталогом (dist-demo/index.html)
```

Для каталога нужны Python 3 и `pip install opencv-python-headless numpy`.

## Распознавание

Итоговое сходство = (нейросеть + 0,3 × цвет) / 1,3. Нейросеть — MobileNetV2 (ImageNet),
выход последнего свёрточного слоя с GeM-пулингом; каждый эталон хранится в 8 поворотах,
поэтому значок можно снимать под любым углом. Модель (`public/model/mnv2.onnx`, 9 МБ)
и движок (`public/ort/`, 15 МБ, ≈4 МБ в gzip) грузятся в фоне при первом запуске, дальше — из кэша.
Если нейросеть не загрузилась, распознавание идёт только по цвету.

Точность на 40 значках из альбома (400 синтетических «фото с телефона», `npm run eval`):

| Способ | top-1 | top-3 |
|---|---|---|
| только цвет | 65% | 84% |
| только нейросеть | 83% | 92% |
| нейросеть + цвет | **92%** | **97%** |

Слабее всего — вытянутые значки (Контакт бар, Зенит): при кадрировании кругом в кадр
попадает много фона.

## Каталог значков

### Из фото страницы альбома

```bash
python3 tools/cut_page.py grid catalog_pages/page2.jpg      # сетка координат → page2.grid.jpg
# опишите значки в catalog_pages/page2.json (пример — page1.json): id, name, series, year, box
python3 tools/cut_page.py cut catalog_pages/page2.jpg catalog_pages/page2.json catalog_src
npm run catalog
```

Фон вырезается автоматически (GrabCut), прямоугольник `box` можно задавать с запасом.

### Из отдельных фото

1. Положите фото или сканы в `catalog_src/<id>.png` (или `.jpg`). Значок должен быть
   на однотонном фоне, а лучше — PNG с прозрачностью. `id` может содержать только
   латиницу, цифры, `-` и `_`.
2. Опишите значки в `catalog_src/meta.json`:
   ```json
   [{ "id": "vostok-1961", "name": "Восток-1", "series": "Космос", "year": 1961, "description": "…" }]
   ```
3. Запустите `npm run catalog`. Конвейер отделит фон, выровняет изображение, извлечёт палитру,
   построит SVG-контур и посчитает эмбеддинги. Всё это попадёт в `public/catalog/`.
4. Проверьте точность распознавания: `npm run eval`. Скрипт генерирует искажённые
   «фото с телефона» и считает top-1/top-3.

Сейчас в `catalog_src/` — 40 значков с первой страницы альбома (`catalog_pages/page1.*`).
Названия и серии проставлены по фото — поправьте в `page1.json` и перезапустите нарезку.

**Значки от пользователей (общий каталог без сервера).** Пользователь загружает фото
значка в альбом сообщества [«Новые значки»](https://vk.com/album-243034935_312442377)
с подписью «Название / Серия / Год». GitHub Actions каждые 3 часа забирает новые фото
(`tools/sync_vk_album.py`), пересобирает каталог и сбрасывает кэш jsDelivr — значок
появляется у всех без перевыкладки приложения. Удалили фото из альбома — значок
пропадёт при следующем обновлении. Нужны секрет `VK_SERVICE_TOKEN` (сервисный ключ
приложения) и переменная `VK_ALBUM_ID=312442377` в настройках репозитория.

**Обновление каталога без перевыкладки приложения.** Храните репозиторий на GitHub и
пропишите в `.env.production`:
`VITE_CATALOG_URL=https://cdn.jsdelivr.net/gh/<user>/<repo>@main/public/catalog/`.
Тогда workflow `.github/workflows/catalog.yml` будет сам пересобирать каталог
при каждом изменении `catalog_src/`. Учтите, что jsDelivr кэширует ветку `@main`
до 12 часов. Для мгновенного обновления ссылайтесь на тег или коммит.

## Публикация во ВКонтакте

1. Создайте мини-приложение: https://vk.com/apps?act=manage → «Создать» → «Мини-приложение».
2. Впишите его ID в `vk-hosting-config.json` (`"app_id"`).
3. `npm run deploy`: сборка и выкладка на хостинг VK. При первом запуске утилита
   попросит подтвердить вход через ВКонтакте.
4. Для отладки на телефоне до выкладки: `npm run dev`, затем `npx @vkontakte/vk-tunnel`.
   Полученный адрес укажите в настройках приложения как адрес для разработки.

## Где лежат данные пользователя

VK Storage — это до 1000 ключей на пользователя, до 4096 байт на значение,
до 1000 записей в час, ключ живёт год.

- `v1_index` — список коллекций и дата продления;
- `v1_c_<id>` — коллекция: название, описание, отслеживаемые серии, цель, имеющиеся значки.
  Длинные значения автоматически режутся на части;
- `v1_note_<badgeId>` — заметка пользователя о значке.

Запись откладывается на 0,6 с и склеивается. Раз в 30 дней ключи перезаписываются, чтобы не истёк срок.
Фото пользователя никуда не загружаются: обработка идёт в памяти телефона.

## Устройство

```
src/
  recognition/descriptor.ts  дескриптор (цвет, радиальный профиль, границы, гармоники)
  recognition/recognize.ts   поиск ближайших значков
  catalog/catalog.ts         загрузка каталога и эмбеддингов
  storage/kv.ts              VK Storage + запасной localStorage
  store/collections.ts       коллекции, статистика профиля
  panels/                    экраны: Home, CollectionView, EditCollection, Crop, Result, BadgeCard, Pick
tools/
  build_catalog.py           фон → выравнивание → палитра → SVG-контур
  embed.ts                   эмбеддинги эталонов (тот же код, что в приложении)
  eval.ts                    проверка точности
```

## Ограничения и что дальше

- Точность измерена на синтетике из того же фото, что и эталоны. На реальных повторных
  съёмках (другой свет, блики эмали) она будет ниже. Лучше всего добавлять в каталог по
  2–3 фото каждого значка — каждое станет отдельным эталоном.
- Векторы нейросети — ≈10 КБ на значок (`embeddings-nn.bin`): 1000 значков ≈ 10 МБ.
  Для больших каталогов стоит сжать размерность (PCA до 256) или взять модель-ретривер
  (DINOv2-small) — код распознавания менять не придётся, только `src/recognition/nn.ts`.
- VK Storage пишется с клиента. Это подходит для личной коллекции, но не для рейтингов
  и обмена между пользователями.
- Предложение нового значка — это ссылка `VITE_SUGGEST_URL`, например на сообщения сообщества.
  Модерация и пополнение каталога — вручную через репозиторий.
